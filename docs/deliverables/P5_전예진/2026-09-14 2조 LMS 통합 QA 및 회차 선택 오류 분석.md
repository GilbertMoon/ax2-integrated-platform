* 팀 편성 결과 저장 확인

## 5. GitHub OAuth 로컬 환경 문제 확인 및 해결

로컬 통합환경에서 GitHub OAuth 로그인이 정상 동작하지 않는 현상을 확인하였다.

환경변수의 실제 로딩값을 Django Shell에서 확인하였다.

```python
from django.conf import settings
print(repr(settings.GITHUB_OAUTH_CLIENT_ID))
```

확인 결과 Client ID 자체는 정상적으로 로딩되고 있었으며, 관련 설정을 재점검하여 로컬 GitHub OAuth 로그인 연동 문제를 해결하였다.

### 결과

* GitHub OAuth Client ID 로딩 확인
* 로컬 로그인 연동 정상화
* LMS GitHub 연동 기능의 추가 Regression 가능성 제거

## 7. LMS 현재 회차 선택 오류 분석

통합 QA 중 현재 회차가 변경되었음에도 LMS에서 이전 회차를 계속 사용하는 현상을 확인하였다.

Claude Code를 이용하여 회차 조회 로직을 코드 단위로 분리하여 재현하였다.

### 재현 결과

```text
최초 현재 회차 조회
→ 67

조회 대상 데이터를 신규 회차로 변경
→ 69

기존 상태에서 다시 조회
→ 67

캐시를 사용하지 않고 직접 재조회
→ 69
```

즉 실제 조회 대상 데이터는 신규 회차로 변경되었지만 LMS 내부 조회 함수에서는 이전 값인 67을 계속 반환하였다.

---

## 8. 원인 분석

문제 지점은 LMS의 다음 회차 조회 함수이다.

```text
lms accounts_client/services.py
_current_round_id()
```

해당 함수의 조회 결과가 캐시에 저장되어 있으며 캐시에 별도의 만료 조건이 존재하지 않는 구조임을 확인하였다.

따라서 최초 호출 시 회차 67이 저장되면 이후 Core의 현재 회차가 69로 변경되어도 LMS 프로세스에서는 기존 캐시값 67을 계속 사용할 수 있다.

### 원인

```text
Core 현재 회차 변경
67 → 69

       ↓

_current_round_id()

       ↓

기존 캐시 67 존재

       ↓

DB 재조회 생략

       ↓

LMS에서는 계속 67 사용
```

## 9. 수정 방향

이번 문제는 Core DB 구조 또는 회차 데이터 모델을 변경할 문제는 아닌 것으로 판단하였다.

기존 회차 선택 우선순위는 유지하고 LMS의 현재 회차 캐시 처리만 수정하는 것이 최소 변경 방향이다.

### 최소 수정 후보

* `_current_round_id()` 캐시 제거

또는

* 일정 시간 이후 캐시 만료
* 회차 변경 시 캐시 무효화

현재 통합 구조에서는 현재 회차 정보가 자주 조회되는 데이터이지만 회차 변경 자체는 빈번하지 않으므로 수정 후 시스템 영향까지 고려하여 최종 방식을 결정할 필요가 있다.

## 10. 현재 확인 범위

이번 회차 오류 재현은 조회 로직을 분리한 격리 테스트에서 확인하였다.

따라서 다음 항목은 추가 확인이 필요하다.

* 서버 Core DB VIEW에 신규 회차 데이터가 실제 존재하는지 확인
* LMS가 해당 VIEW를 통해 동일 회차를 조회하는지 확인
* 캐시 제거 후 신규 회차가 즉시 반영되는지 확인
* 실제 화면에서 회차가 정상 전환되는지 확인

현재 단계에서는 **캐시가 이전 회차를 유지하는 현상 자체와 원인은 재현 완료**한 상태이다.

## 11. File Storage 운영기준 확인

기존 LMS 통합 과정에서는 다음 폴더명이 사용되었다.

```text

```

통합 운영 기준에서는 조 번호가 아닌 기능명을 기준으로 Namespace를 표준화하기로 하였다.

```text
files/
├── core/
├── game/
├── lms/
├── prd/
└── face-recognition/
```

따라서 LMS의 최종 운영경로는 다음과 같다.

```text
files/lms/
```

* `LMS_MEDIA_ROOT` 환경변수 반영
* Ubuntu Host 경로 확인
* Docker Volume 사용 시 Volume 매핑 확인
* 실제 파일 업로드
* 파일 조회
* 파일 재다운로드

## 14. QA 판단

### 현재 상태

**YELLOW**

### 판단 근거

2조 LMS와 4조 Core의 주요 통합 기능과 점수 연동 흐름은 정상 동작하는 것을 확인하였다.

학생 E2E, LMS 점수 생성, Core 최종점수 반영, LMS 기반 팀 편성까지 주요 통합 흐름은 검증 완료하였다.

또한 PR Merge 이후 기능 Cross Check와 서버 LMS DB 준비 상태, GitHub OAuth 환경 문제까지 확인하였다.

다만 최종 QA 과정에서 **현재 회차 변경 후 LMS가 이전 회차를 계속 사용하는 캐시 문제**가 새롭게 확인되었다.

해당 문제의 원인은 `_current_round_id()`의 만료 없는 캐시로 특정하였으나 아직 실제 코드 수정 및 Regression이 완료되지 않았다.

또한 최신 `develop` 전체 Regression과 File Storage 실제 운영경로 변경 검증이 남아 있다.

따라서 현재 단계는 통합 실패 상태는 아니지만 최종 완료 처리 전 수정 및 Regression이 필요한 **YELLOW** 상태로 판단한다.
