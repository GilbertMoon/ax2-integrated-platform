## 4. GitHub 링크 제출 정책 최신화

2조 최신 `develop`에서 적용하고 있는 GitHub 제출 정책을 다시 확인하였다.

기존 통합본에 남아 있던 보류 정책을 최신 원본 정책 기준으로 정리하였다.

### GitHub 제출 허용 기준

* 정상 GitHub `blob` 파일 링크 → 제출 허용

### 제출 차단 기준

* GitHub 저장소 Root URL → 제출 차단

* GitHub `tree` 폴더 URL → 제출 차단

* 존재하지 않는 GitHub URL → 제출 차단

* Private Repository 또는 접근 권한 부족 → 제출 차단

### 외부 장애 처리 기준

GitHub API 자체의 일시적인 장애가 학생 제출 실패로 이어지지 않도록 정책을 확인하였다.

    GitHub API timeout
    GitHub API 5xx
        ↓
    학생 제출 차단하지 않음

반면 실제 잘못된 제출 링크인 경우에는 차단한다.

    Repository Root
    Tree URL
    Not Found
    Private / Permission Denied
        ↓
    제출 차단

일반 URL은 GitHub URL 검증 대상에서 제외하도록 유지하였다.

### 테스트

* 정상 blob URL 테스트

* Repository Root URL 차단 테스트

* Tree URL 차단 테스트

* 존재하지 않는 URL 테스트

* Private Repository 테스트

* Timeout / 5xx 테스트

* 일반 URL 테스트

* 파일 제출 테스트

* 실제 브라우저 수동 제출 QA

이를 통해 GitHub API 자체 장애와 학생이 입력한 잘못된 GitHub URL을 구분하여 처리하도록 정리하였다.

## 7. 지각 제출 정책 검증

LMS의 지각 제출 및 감점 정책을 코드 기준으로 확인하였다.

### 지각 판정 기준

    submitted_at > due_at

개인 과제와 팀 과제 모두 동일한 기준을 사용하는 것을 확인하였다.

### 감점 기준

지각 감점은 AI 점수에 직접 적용되는 것이 아니라 튜터 최종 평가 점수를 기준으로 적용되는 구조임을 확인하였다.

과제별 설정값:

    late_penalty

만큼 고정 점수를 차감한다.

### 점수 하한

필수 과제와 선택 과제는 각각 점수 하한을 사용한다.

    필수 과제 기본 하한 : 40
    선택 과제 기본 하한 : 20

### 제출 정책

* 마감 이후 최초 제출은 지각 제출로 처리 가능

* 마감 이후 재제출은 차단

* 개인 / 팀 과제 동일 기준 확인

* 지각 감점 결과가 LMS 최종 점수에 반영

* 지각 감점 결과가 `RoundScore.total`에 반영

* 최종적으로 Core LMS 평가 점수까지 전달

* 튜터 화면에서 지각 여부 표시 확인

이를 통해 지각 제출 상태가 단순 UI 표시뿐 아니라 실제 LMS 점수 및 Core 평가 점수까지 연결되는 것을 확인하였다.

## 10. LMS 점수 → 팀 편성 반영 검증

LMS 점수가 Core 최종 평가뿐 아니라 팀 편성 점수에도 사용되는 구조를 확인하였다.

다만 팀 편성에서 사용하는 LMS 점수 경로는 공식 Core 평가 계산과 동일하지 않음을 확인하였다.

### 공식 Core 평가

    LMS RoundScore
        ↓
    Core EvaluationResult
        ↓
    최종 평가

### 팀 편성

    기존 평가 결과
        ↓
    Base Score

    선택된 LMS 과제
        ↓
    실시간 LMS grading
        ↓
    LMS Score

    Base + LMS
        ↓
    설정된 가중치 혼합
        ↓
    팀 편성 Seed Score

### 확인 내용

* 과거 `EvaluationResult` 기반 Base Score 계산 확인

* `RoundScore`가 아직 없는 상태에서도 팀 편성 LMS 점수 계산 가능 확인

* Base Score + LMS Score 가중 혼합 공식 확인

* Round 69 학생 샘플 데이터를 이용해 직접 계산값 비교

이를 통해 공식 Core 평가와 팀 편성은 서로 다른 LMS 점수 조회 경로를 사용하는 구조임을 확인하였다.

## 11. RoundScore 비참가자 포함 현상 확인

LMS `grading.snapshot()`의 대상 학생 범위를 확인하는 과정에서 회차 참가자가 아닌 학생까지 RoundScore 생성 대상이 될 수 있는 구조를 확인하였다.

### Round 69 기준

    Core 회차 참가자     : 28명
    전체 승인/활성 학생  : 37명
    예상 RoundScore      : 37건
    비참가자             : 9명

### 원본 확인 결과

2조 원본 코드와 테스트를 확인한 결과 `snapshot()`은 해당 회차 참가자만 대상으로 하는 것이 아니라 전체 승인/활성 학생을 기준으로 생성하는 구조였다.

따라서 해당 현상은 통합 과정에서 새롭게 발생한 오류가 아닌 2조 원본 설계임을 확인하였다.

### 영향 분석

Core 공식 평가는 별도로 회차 참가자를 기준으로 처리하므로 비참가자의 RoundScore 행이 존재하더라도 Core 최종 평가에는 자동으로 포함되지 않는다.

팀 편성 역시 해당 RoundScore를 직접 사용하는 구조가 아니므로 영향이 없음을 확인하였다.

따라서 DB에서 비참가자 RoundScore 자체를 삭제하거나 원본 snapshot 로직을 변경하지 않았다.

## 18. QA 판단

### 현재 상태

**GREEN**

### 판단 근거

2조 LMS 최신 변경사항을 기존 4조 통합 구조를 유지하면서 필요한 기능 단위로 반영하였다.

GitHub OAuth 및 GitHub URL 제출 정책을 최신 2조 기준으로 다시 확인하였으며 정상 파일 URL과 잘못된 Repository/Tree URL, 외부 API 장애 상황을 구분하여 처리하는 것을 검증하였다.

학생 과제 목록에서 마감된 미제출 과제가 사라지는 UI 공백을 확인하고 기존 제출 정책을 변경하지 않는 범위에서 읽기 전용 "마감된 과제" 영역을 추가하였다.

지각 제출 및 감점 정책도 실제 점수 계산 경로까지 확인하였으며 `RoundScore`를 통해 Core 평가 점수로 전달되는 구조를 검증하였다.

또한 공식 Core 평가와 팀 편성에서 LMS 점수를 사용하는 방식이 서로 다른 구조임을 확인하고 각각 정상 계산되는 것을 검증하였다.

RoundScore 생성 시 비참가자가 포함될 수 있는 부분은 2조 원본 설계임을 확인하였으며, Core 공식 평가 및 팀 편성 계산에는 영향이 없음을 검증하였다.

원본 데이터 생성 로직을 변경하지 않고 LMS 결과 화면과 CSV에서 실제 회차 참가자만 조회되도록 최소 보완하였다.

최종적으로 최신 `develop`까지 병합한 후 전체 자동 테스트 706개가 통과하였고, 학생/튜터 주요 기능 및 GitHub, 평가, 팀 편성, 공통 화면에 대한 수동 Regression도 완료하였다.

따라서 2026-09-15 기준 P5 담당 2조 LMS 최신 통합 및 QA 작업은 **GREEN** 상태로 판단한다.

## 19. 작업 결과

2조 LMS 최신 변경사항을 4조 통합 플랫폼의 기존 인증, DB Router, Slack, GitHub 및 File Storage 구조를 보호하면서 선택적으로 반영하였다.

GitHub OAuth 및 제출 URL 정책을 최신화하고, 학생 과제 화면의 마감 과제 누락 문제를 보완하였다.

지각 제출 정책과 감점 결과가 LMS 점수 및 Core 평가까지 연결되는 흐름을 확인하였으며 Round 69를 기준으로 `RoundScore`, `EvaluationResult`, LMS 가중치 및 최종 점수 생성 조건을 검증하였다.

또한 LMS 점수가 팀 편성에서 공식 Core 평가와 다른 실시간 계산 경로로 사용되는 것을 확인하고 실제 계산 결과가 일치하는지 검증하였다.

RoundScore에 비참가자가 포함되는 원본 LMS 설계는 유지하되 사용자에게 노출되는 결과 화면과 CSV에서는 실제 회차 참가자만 표시되도록 보완하였다.

최종적으로 최신 `develop` 병합 이후 전체 자동 테스트 706개가 통과하였으며 학생/튜터 및 공통 기능에 대한 수동 Regression까지 완료하였다.
