# 2026-09-08 2조 LMS Core 통합 및 기능 QA

## 1. 목적

- 2조 LMS 기능을 기존 4조 Core의 사용자·팀·회차 데이터 구조와 연결한다.
- LMS 과제 점수를 기존 Core 평가 결과 계산에 반영할 수 있도록 통합 구조를 구성한다.
- 통합 후 학생·튜터 주요 화면을 직접 점검하여 실제 기능 동작 여부를 확인한다.
- 전체 자동 테스트와 Regression 테스트를 통해 기존 4조 기능에 영향이 없는지 확인한다.
- 통합 과정에서 발견된 오류를 별도 후속 QA 대상으로 정리한다.

---

## 2. 2조 LMS → 4조 Core 통합

### 2.1 공통 데이터 연결

2조 LMS가 별도의 사용자·팀 데이터를 독립적으로 사용하는 구조가 아니라 기존 4조 Core의 공통 데이터를 기준으로 동작하도록 연결하였다.

주요 연결 대상은 다음과 같다.

```text
4조 Core
accounts.User
    ↓
rounds.EvaluationRound
    ↓
teams.Team / TeamMembership
    ↓
2조 LMS
강의 / 과제 / 제출 / 점수
```

### 2.2 통합 작업 내용

- 2조 LMS 기능을 통합 프로젝트의 `lms/` 영역에 연결
- LMS 모델 및 학생 강의 관련 View 연결
- LMS URL 구조를 통합 프로젝트 URL 구조와 연결
- LMS에서 필요한 DB Router 구성 확인 및 연결
- 기존 Core 로그인 및 사용자 정보 연결
- 기존 Core Team / Round 데이터 연결
- LMS와 Core 사이의 연결 계층인 `lms_client/` 구성
- LMS 점수 조회를 위한 Service 구조 연결

---

## 3. LMS 점수 → Core 평가 점수 반영 구조

LMS 과제 점수를 기존 4조 평가 시스템의 최종 결과 계산에 포함할 수 있도록 관련 구조를 추가하였다.

### 3.1 주요 반영 내용

- 평가 회차별 LMS 반영 비율을 관리하기 위한 `lms_score_weight` 추가
- 관련 DB Migration 작성 및 적용
- LMS 원본 점수를 저장하기 위한 `lms_score_raw` 구조 추가
- LMS 0~100점 점수를 Core 평가 점수 체계에 맞게 변환하는 로직 연결
- 기존 평가 점수와 LMS 점수를 함께 계산할 수 있도록 점수 계산 구조 수정
- LMS 점수 조회 Service와 Core 평가 결과 계산 연결

### 3.2 점수 반영 흐름

```text
LMS 과제 점수
    ↓
LMS 점수 조회 Service
    ↓
lms_score_raw
    ↓
0~100점 → Core 평가 점수 체계 변환
    ↓
회차별 lms_score_weight 적용
    ↓
기존 Core 평가 점수와 함께 최종 결과 계산
```

현재 코드 구조상 LMS 점수를 Core 평가 계산에 포함할 수 있도록 연결되었으며, 실제 평가 대상 과제를 이용한 최종 점수 반영 검증은 후속 QA 항목으로 남겨두었다.

## 4. DB 및 기존 데이터 연동 점검

통합 과정에서 기존 Core 데이터와 LMS 화면이 정상적으로 연결되는지 확인하였다.

### 확인 항목

- Core User 데이터와 LMS 사용자 연결
- Core Team 데이터와 LMS 팀 정보 연결
- EvaluationRound와 LMS 데이터 연결
- 신규 팀 편성 후 학생 소속 팀 데이터 재확인
- 기존 테스트 데이터에서 발생한 `내 팀` 조회 오류 확인
- 팀 관련 데이터 정리 후 조회 복구 확인

### 확인 결과

통합 테스트 중 기존 테스트 데이터의 팀 구성 상태와 현재 회차의 팀 편성 데이터가 일치하지 않아 `내 팀` 조회 과정에서 오류가 발생하였다.

이후 팀을 새로 편성하고 관련 데이터를 다시 확인한 결과, 변경된 팀 구성원이 정상적으로 조회되는 것을 확인하였다.

## 5. 자동 테스트 및 Regression 테스트

통합 작업 이후 전체 테스트를 실행하여 기존 기능 영향 여부를 확인하였다.

### 테스트 결과

```text
462 tests passed
1 skipped
```

### 확인 내용

- 통합 후 전체 자동 테스트 실행
- 총 462개 테스트 통과
- 1개 테스트 Skip 확인
- LMS 통합으로 인해 기존 Core 테스트가 대량 실패하지 않는 것 확인
- 사용자 / 팀 / 평가 관련 주요 기능 Regression 기본 검증

자동 테스트 기준으로 LMS 통합으로 인해 기존 프로젝트 전체가 깨지는 수준의 문제는 확인되지 않았다.

## 9. 확인된 이슈

### 9.1 과제 삭제 기능 오류

통합 QA 중 과제 삭제 기능에서 오류가 발생하는 것을 확인하였다.

현재까지 확인한 내용은 다음과 같다.

- 과제 삭제 기능 오류 발생 확인
- 전체 LMS 장애가 아닌 특정 기능 오류로 분리

후속 확인 필요 항목:

- 과제 삭제 요청 흐름 확인
- 관련 View / URL 확인
- FK 또는 참조 데이터로 인한 삭제 제한 여부 확인
- 오류 수정 후 재테스트

### 9.2 LMS 점수 실제 Core 결과 반영 최종 검증 필요

코드 구조상 LMS 점수와 Core 평가 계산은 연결되었지만, 실제 평가 데이터를 사용한 최종 결과 검증이 추가로 필요하다.

```text
평가 대상 과제 생성
    ↓
학생 과제 제출
    ↓
LMS 점수 생성
    ↓
lms_score_raw 저장 확인
    ↓
lms_score_weight 적용 확인
    ↓
Core 평가 결과 재계산
    ↓
학생/튜터 결과 화면 최종 점수 확인
```

## 12. 결론

2조 LMS를 기존 4조 Core의 사용자·팀·회차 구조와 연결하고, LMS 점수를 기존 평가 결과 계산에 포함하기 위한 통합 구조를 구성하였다.

통합 후 전체 자동 테스트에서 462개 테스트가 통과하였으며, 학생 및 튜터 주요 화면 12개에 대해 실제 조회 상태를 확인하였다.

통합 QA 과정에서 기존 팀 데이터 문제로 발생했던 `내 팀` 조회 오류는 신규 팀 편성 및 데이터 정리 후 정상화되었다.

현재 LMS 통합 자체는 상당 부분 완료된 상태이며, 최종 완료 판단을 위해서는 과제 삭제 오류 수정과 실제 LMS 과제 점수가 Core 최종 평가 점수에 정상적으로 반영되는지에 대한 추가 검증이 필요하다.
