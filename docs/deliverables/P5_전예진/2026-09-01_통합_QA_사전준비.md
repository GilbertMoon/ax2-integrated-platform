# 통합 QA 사전 준비

## 1. 2조 LMS ↔ 4조 Core 통합 범위

### 통합 대상

| 영역 | 기준 | QA 확인 내용 |
|---|---|---|
| 회원/사용자 | 4조 Core | LMS에서 동일 사용자를 정상적으로 인식하는지 확인 |
| 팀/조 편성 | 4조 Core | LMS와 연동이 필요한 경우 4조 팀 정보를 기준으로 사용하는지 확인 |
| 회차 | 4조 Core | 과제/학습과 회차 연동이 필요한 경우 정상 연결되는지 확인 |
| 평가 | 4조 Core | 2조 평가 기능은 통합하지 않고 4조 평가 기능 사용 |
| 결과 | 4조 Core | 기존 평가 결과 기능 유지 및 통합 영향 여부 확인 |
| 강의 | 2조 LMS | 강의 조회 및 접근 정상 여부 확인 |
| 과제 | 2조 LMS | 과제 생성/조회 및 대상 정보 정상 여부 확인 |
| 제출 | 2조 LMS | 과제 제출 및 제출 상태 정상 여부 확인 |
| GitHub Sync | 2조 신규 기능 | 과제 제출 후 GitHub 동기화 정상 여부 확인 |
| Slack Bot | 4조 개발 | LMS 미제출 학생 정보와 Slack 독려 기능의 연동 확인 |

> 실제 코드 통합 시 User / Team / Round의 FK 및 데이터 연결 구조를 우선 확인한다.

## 2. LMS 강의·과제·제출 통합 테스트 항목

### 강의

- [ ] 학생 로그인 후 강의 목록 조회
- [ ] 강의 상세 조회
- [ ] 정상적인 권한으로 강의 접근
- [ ] 권한이 없는 데이터에 접근할 수 없는지 확인

### 과제

- [ ] 과제 목록 조회
- [ ] 과제 상세 조회
- [ ] 과제 마감일 정상 표시
- [ ] 대상 학생에게 과제가 정상적으로 노출되는지 확인
- [ ] 과제와 회차/대상 정보가 정상적으로 연결되는지 확인

### 제출

- [ ] 학생이 과제를 정상적으로 제출할 수 있는지 확인
- [ ] 제출 데이터가 정상적으로 저장되는지 확인
- [ ] 제출 상태가 정상적으로 변경되는지 확인
- [ ] 본인의 제출물을 정상적으로 조회할 수 있는지 확인
- [ ] 마감 전 재제출이 정상적으로 동작하는지 확인
- [ ] 마감 후 제출 제한이 정상적으로 적용되는지 확인
- [ ] 지각 제출 허용 설정 시 마감 후 제출이 정상적으로 처리되는지 확인
- [ ] 허용되지 않은 파일 업로드가 차단되는지 확인
- [ ] `.ipynb` 파일 형식 및 JSON 구조 검증이 정상 동작하는지 확인

### GitHub 연동 예외

- [ ] GitHub 연결을 하지 않은 상태에서도 과제 제출이 가능한지 확인
- [ ] GitHub API 오류가 발생해도 LMS 과제 제출 자체는 정상 처리되는지 확인
- [ ] GitHub 관련 환경변수가 없어도 기존 LMS 기능에 영향이 없는지 확인

## 3. 4조 평가 기능과 LMS 영역 분리 확인

현재 통합 방향에 따라 2조의 평가 기능은 통합 대상에서 제외하고 4조 평가 기능을 사용한다.

- [ ] 기존 4조 평가 화면 정상 동작
- [ ] 기존 평가 데이터 정상 유지
- [ ] LMS 통합으로 평가 기능에 영향이 없는지 확인
- [ ] LMS 과제/제출 기능과 4조 평가 데이터가 잘못 연결되지 않는지 확인

## 4. GitHub API 연동 테스트 시나리오

### 정상 시나리오

학생이 GitHub를 연결한 상태에서 과제를 제출한다.

`학생 로그인 → GitHub 연결 → 과제 제출 → GitHub 저장소 동기화 → Commit/Push`

- [ ] GitHub 연결 정상
- [ ] 올바른 GitHub 계정과 연결
- [ ] 과제 제출 정상
- [ ] 제출물이 학생 본인 GitHub 저장소에 생성/업데이트
- [ ] Commit 정상 생성
- [ ] Push 정상 처리

### 예외 시나리오

`GitHub 미연결 → 과제 제출`

- [ ] LMS 과제 제출은 정상 처리
- [ ] GitHub 기능이 기존 제출 흐름을 방해하지 않는지 확인

`GitHub API 오류 → 과제 제출`

- [ ] LMS 과제 제출은 정상 처리
- [ ] GitHub 동기화 실패가 별도로 처리되는지 확인
- [ ] 재시도 대상이 정상적으로 처리되는지 확인

`GitHub 환경변수 미설정 → LMS 사용`

- [ ] GitHub Sync가 비활성화되는지 확인
- [ ] 기존 LMS 과제/제출 기능은 정상 동작하는지 확인

### 추가 확인

- [ ] 마감 최종본 커밋 기능 정상 동작
- [ ] 재시도 배치 동작 확인

## 5. Slack Bot 통합 QA 준비

### 2조 요구사항

2조 LMS에서 **미제출 학생에 대해 튜터가 버튼을 눌러 과제 제출을 독려하는 기능**이 필요함.

### 통합 흐름

`LMS 제출 현황 → 미제출 학생 식별 → Slack Bot → 튜터에게 대상 표시 → 독려 버튼 실행 → 대상 학생에게 독려`

### 데이터 연동 확인

- [ ] LMS에서 미제출 학생 정보가 정확하게 전달되는지 확인
- [ ] 제출 완료 학생은 독려 대상에서 제외되는지 확인
- [ ] 튜터에게 정확한 미제출 학생 정보가 표시되는지 확인

### 버튼 동작 확인

- [ ] 튜터가 Slack에서 독려 버튼을 확인할 수 있는지 확인
- [ ] 독려 버튼 클릭이 정상 동작하는지 확인
- [ ] 정확한 대상 학생에게 독려가 전달되는지 확인
- [ ] 중복 독려가 발생하지 않는지 확인

### 오류 영향 확인

- [ ] Slack 전송 실패가 LMS 과제 제출 기능에 영향을 주지 않는지 확인
- [ ] 잘못된 학생 정보가 전달되지 않는지 확인
- [ ] 이미 제출한 학생에게 잘못된 독려가 전달되지 않는지 확인

## 6. 전체 통합 Regression 테스트 범위

신규 기능 통합 후 기존 기능이 정상적으로 유지되는지 전체 흐름을 확인한다.

### Core 영역

- [ ] 로그인
- [ ] 사용자 정보
- [ ] 팀/조 편성
- [ ] 회차
- [ ] 평가
- [ ] 결과

### LMS 영역

- [ ] LMS 접근
- [ ] 강의 조회
- [ ] 과제 조회
- [ ] 과제 제출
- [ ] 제출 결과 조회

### 신규 연동 영역

- [ ] GitHub Sync
- [ ] Slack Bot 연동
- [ ] 뉴페이스 모드 통합 후 기존 조 편성 기능 정상 여부

> 실제 Regression 테스트는 각 기능의 개발 및 통합이 완료된 이후 진행한다.
