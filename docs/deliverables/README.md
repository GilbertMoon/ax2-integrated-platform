# Daily Deliverables Guide

## 목적
모든 담당자는 매일 작업 종료 전 그날의 산출물을 GitHub에 제출합니다. 산출물은 작성자 본인이 아닌 다른 사람이 읽어도 목적, 수행 내용, 결과, 검증 방법을 이해할 수 있어야 합니다.

## 제출 위치
- P1: `docs/deliverables/P1/`
- P2: `docs/deliverables/P2/`
- P3: `docs/deliverables/P3/`
- P4: `docs/deliverables/P4/`
- P5: `docs/deliverables/P5/`
- P6: `docs/deliverables/P6/`

## 파일명 규칙
`YYYY-MM-DD_업무명.md`

예시:
- `2026-08-28_baseline_report.md`
- `2026-08-28_user_student_role_analysis.md`
- `2026-08-28_lms_integration_review.md`

## 매일 제출 순서
1. 오늘 TODO 확인
2. 업무 수행
3. 결과를 담당자 폴더의 MD 파일로 작성
4. 관련 Issue / PR / Commit / 문서 경로를 기록
5. 본인 검증
6. 다른 담당자 Cross Check
7. 보완사항 반영
8. 검증 통과 후 GREEN 처리
9. 필요 시 Notion에 GitHub 산출물 링크 연결

## GREEN 기준
아래 항목을 모두 만족해야 GREEN입니다.

- [ ] 오늘 TODO가 완료되었다.
- [ ] 실제 산출물 파일이 GitHub에 존재한다.
- [ ] 목적과 결과가 제3자에게 이해된다.
- [ ] 재현/확인 방법이 있다.
- [ ] 관련 Issue / PR / Commit / 문서가 연결되어 있다.
- [ ] 본인 검증이 PASS다.
- [ ] Cross Check가 PASS다.
- [ ] 필요한 경우 Notion에 링크가 연결되어 있다.
