# 신규 차수 생성 Backend 로직

- 담당: P3 김종복
- 작업일: 2026-09-04
- Branch: `feature/p3-jb`
- 상태: 구현 내용 산출물 정리

## 1. 작업 목적

신규 프로젝트 차수 생성 요청을 Backend에서 처리하고, 기존 `rounds_evaluationround` 회차와 `project_info` 프로젝트 정보를 연결하여 하나의 프로젝트 차수로 관리한다.

프로젝트 차수는 별도의 신규 모델이 아니다. 현재 DB의 `rounds_evaluationround` 각 회차를 프로젝트 차수로 사용하고, `project_info.evaluationround_id`를 통해 프로젝트 정보를 연결한다.

## 2. Backend 처리 구조

```text
Web 신규 프로젝트 차수 생성 요청
        ↓
Backend 입력값 검증
        ↓
EvaluationRound 생성
        ↓
project_info 생성
        ↓
project_info.evaluationround_id 연결
        ↓
생성 완료
        ↓
프로젝트 회차 상세 화면 이동
```

## 3. 주요 데이터 생성

### 3.1 `rounds_evaluationround`

신규 회차의 기본 및 평가 관련 데이터를 저장한다.

주요 대상 필드 예시:

- `title`
- `description`
- `status`
- `evaluation_start_at`
- `evaluation_end_at`
- 평가 가중치 및 템플릿 관련 설정

### 3.2 `project_info`

신규 회차에 대한 프로젝트 정보를 저장한다.

주요 대상 필드:

- `name`
- `description`
- `team_start`
- `team_end`
- `evaluationround_id`

## 4. 회차 연결 방식

신규 회차가 생성되면 생성된 `rounds_evaluationround.id`를 `project_info.evaluationround_id`에 저장한다.

```text
EvaluationRound.id
        │
        ▼
project_info.evaluationround_id
```

예시:

```text
rounds_evaluationround
id = 63

project_info
evaluationround_id = 63
name = "4차 프로젝트"
```

이렇게 하면 동일한 회차를 프로젝트 관점과 평가 관점에서 함께 사용할 수 있다.

## 5. Transaction 처리

신규 회차 생성과 `project_info` 연결은 하나의 생성 작업으로 처리하는 것을 기준으로 한다.

```text
BEGIN
  EvaluationRound 생성
  project_info 생성 및 FK 연결
COMMIT
```

중간 단계에서 오류가 발생하면 전체 생성 작업이 정상적으로 완료되지 않도록 transaction 단위로 처리하는 것을 원칙으로 한다.

## 6. 유효성 검증

### 프로젝트 정보

- 프로젝트명 필수 여부 검증
- 프로젝트 설명 처리
- 팀 구성 시작일/종료일 검증
- 시작일 < 종료일 검증

### 평가 정보

- 평가 기간의 유효성 검증
- 상태값 검증
- 필요한 평가 설정값의 기본값 적용

## 7. 예외 처리

다음과 같은 상황에서는 생성 작업을 정상 완료하지 않는다.

- 필수 입력값 누락
- 잘못된 날짜 범위
- 평가 회차 데이터 검증 실패
- `project_info` 연결 실패
- DB 저장 과정에서 오류 발생

DB 저장 오류가 발생하는 경우 신규 회차만 남거나 프로젝트 정보만 남는 불완전한 상태가 발생하지 않도록 transaction 단위 처리를 적용한다.

## 8. 기존 구조와의 관계

이번 Backend 로직에서는 다음과 같은 DB 구조 변경을 하지 않는다.

```text
❌ ProjectRound 신규 모델 생성
❌ rounds_evaluationround 신규 대체 테이블 생성
❌ 기존 회차 테이블 변경
❌ project_info FK 구조 변경
```

기존 구조를 그대로 활용한다.

```text
rounds_evaluationround
        │
        │ FK
        ▼
project_info
```

## 9. 관련 Backend 파일

- `rounds/views.py`
- `rounds/project_views.py`
- `rounds/services.py`
- `rounds/models.py`
- `rounds/urls.py`

실제 구현 시 기존 평가 회차 생성/수정 로직과 프로젝트 회차 생성 로직의 책임이 혼재되지 않도록 구분한다.

## 10. Migration 여부

이번 작업의 데이터 모델 정의 자체는 기존 `rounds_evaluationround` 및 `project_info`를 사용한다.

따라서 신규 모델/필드 추가가 없다면 별도의 schema migration은 필요하지 않다.

확인은 다음 명령으로 수행한다.

```powershell
python manage.py makemigrations --check
python manage.py check
```

## 11. 로컬 검증

다음 항목은 실제 로컬 환경에서 확인해야 한다.

- Django Backend 정상 기동
- 신규 프로젝트 차수 생성 요청 정상 처리
- `rounds_evaluationround` 신규 레코드 생성
- `project_info` 신규 레코드 생성
- `evaluationround_id` 정상 연결
- 잘못된 날짜 입력 시 검증 오류
- 저장 중 오류 발생 시 transaction rollback
- 생성 완료 후 프로젝트 상세 화면 이동
- 해당 회차의 평가 회차 관리 화면 연결

> 본 문서에는 실제 실행하지 않은 테스트 결과를 완료로 기재하지 않는다.
