# Daily Team Feedback 운영 가이드

## 1. 목적

이 폴더는 매일 아침 전날 진행 업무를 확인하고, **오늘 해야 할 일을 모두 GREEN(🟢) 상태로 만들기 위한 실행·검증 가이드**를 기록합니다.

단순히 "했다"고 말하는 것으로 완료 처리하지 않습니다.

**GREEN = 작업 완료 + 결과물 존재 + 본인 검증 + 크로스 검증 통과**

---

## 2. 상태 기준

| 상태 | 의미 |
|---|---|
| ⚪ NOT STARTED | 아직 시작하지 않음 |
| 🔵 DOING | 진행 중 |
| 🟡 SELF CHECK | 작업은 했고 본인 검증 중 |
| 🟠 CROSS CHECK | 본인 검증 완료, 다른 담당자 검증 대기 |
| 🔴 BLOCKED | 오류/의존성 때문에 진행 불가 |
| 🟢 GREEN | 완료조건 + 증빙 + 본인검증 + 크로스검증 모두 통과 |

> 체크박스 `[x]`만 있다고 GREEN이 아닙니다.

---

## 3. GREEN 판정 4단계

모든 작업은 아래 4단계를 모두 통과해야 합니다.

### STEP 1. 작업 완료
- Issue에 적힌 업무를 실제로 수행했는가?
- 완료 기준(DONE 기준)을 충족했는가?

### STEP 2. 결과물 확인
아래 중 최소 1개 이상의 확인 가능한 결과가 있어야 합니다.
- GitHub 파일
- Commit
- Pull Request
- Issue 업데이트/댓글
- 실행 결과
- 테스트 결과
- ERD/문서/스크린샷 등 산출물

### STEP 3. 본인 검증
담당자가 직접 다시 확인합니다.
- 파일이 실제 Repository에 존재하는가?
- 코드/문서가 열리는가?
- 실행해야 하는 기능이면 실제 실행되는가?
- Issue에 적은 내용과 실제 결과가 같은가?

### STEP 4. 크로스 검증
다른 담당자가 결과를 다시 확인합니다.

검증자는 다음만 확인하면 됩니다.
1. 결과물이 실제 존재하는가?
2. 완료 기준을 충족하는가?
3. 재현 가능한가?
4. 기존 Core 기능을 깨뜨리지 않는가?
5. 문제가 있으면 담당자에게 되돌렸는가?

모두 통과해야 🟢 GREEN입니다.

---

## 4. 권장 크로스 검증 조합

| 작업 담당 | 1차 검증자 | 주요 검증 내용 |
|---|---|---|
| P1 통합/문서 | P3 또는 P5 | 기준 누락, 실제 상태와 문서 일치 여부 |
| P2 User/Student/권한 | P3 | FK, 모델, DB 관계 검증 |
| P3 DB/ERD | P2 또는 P4 | 실제 모델/업무 구조와 ERD 일치 여부 |
| P4 1조 통합 | P3 + P5 | DB 충돌 + 기능 Regression |
| P5 2조/QA | P2 또는 P3 | 공통 데이터 + 테스트 기준 검증 |
| P6 3조/서버 | P3 또는 P5 | DB/환경/실행 결과 검증 |

---

## 5. 매일 아침 진행 순서

### 1) 전날 Issue/PR/Commit/문서 확인
각 담당자의 실제 결과물을 먼저 봅니다.

### 2) 오늘 파일 생성
파일명은 작성일 기준으로 통일합니다.

```text
YYYY-MM-DD.md
```

예:
```text
2026-08-28.md
```

### 3) 담당자별 현재 상태 작성
- 어제 완료한 것
- 미완료된 것
- 증빙 위치
- 오늘 GREEN으로 만들어야 할 항목

### 4) 담당자는 자기 항목 수행
문서의 순서대로 실행하고 체크합니다.

### 5) 본인 검증
본인이 직접 결과를 재확인합니다.

### 6) 크로스 검증
지정된 다른 담당자가 다시 확인합니다.

### 7) GREEN 판정
모든 조건이 맞으면 🟢로 변경합니다.

---

## 6. 완료 기록 형식

각 담당자는 자기 영역에 아래 형식으로 결과를 남깁니다.

```text
[실행 결과]
- 수행 내용:
- 결과물 위치:
- Issue/PR/Commit:
- 실행/테스트 결과:
- 남은 문제:

[본인 검증]
- 결과물 존재: PASS / FAIL
- 완료기준 충족: PASS / FAIL
- 실행/재현 확인: PASS / FAIL

[크로스 검증]
- 검증자:
- 결과: PASS / FAIL
- 확인 내용:
- 수정 필요사항:
```

---

## 7. 절대 GREEN 처리하면 안 되는 경우

아래 중 하나라도 해당하면 GREEN이 아닙니다.

- 말로만 완료했다고 한 경우
- Issue 체크박스만 `[x]`이고 결과물이 없는 경우
- 문서 경로를 적었지만 실제 Repository에 파일이 없는 경우
- 실행 확인 업무인데 실제 실행하지 않은 경우
- 본인만 확인하고 다른 사람이 검증하지 않은 경우
- 오류가 남았는데 이유/다음 조치가 기록되지 않은 경우

---

## 8. 최종 목표

매일 업무 종료 시 오늘의 MUST 항목이 가능한 한 모두 아래 상태가 되도록 합니다.

```text
작업 수행
  ↓
결과물 생성
  ↓
본인 검증 PASS
  ↓
크로스 검증 PASS
  ↓
🟢 GREEN
```

GREEN이 되지 못한 항목은 다음날 문서로 이월하되, 반드시 **왜 못 끝냈는지 / 무엇이 막혔는지 / 다음 액션이 무엇인지** 기록합니다.
