# 공통 식별 기준 초안 (1·2·3조 ↔ 4조 Core)

작성자: P2 심우섭 | 작성일: 2026-08-28

## 1. 회원(User) 기준
- **기준 필드**: `accounts_user.id`
- 별도 User 테이블을 새로 만들지 않고, 1조·2조·3조 모두 이 ID를 회원의 유일한 기준으로 참조
- 로그인은 4조 Core의 `accounts_user`가 전담 (django-allauth로 이메일/소셜 로그인 지원 중)

## 2. 학생(Student) 기준
- **기준 필드**: `accounts_user.id` (학번 대신 내부 id를 학생 매칭 기준으로 확정)
- 별도 Student 테이블은 존재하지 않음 — User와 Student가 하나의 테이블로 통합된 구조
- `student_number` 필드는 존재하지만 현재 비어있어 사용하지 않음 (필요 시 추후 재검토)

## 3. 팀(Team) 참조 규칙
- 팀 소속 정보를 **API로 1조·2조·3조 모두에 제공**하기로 확정
- 현재는 화면에만 노출되어 있어 API화 작업 필요
- 참조 방식(FK 상세 스펙)은 다음 단계에서 확정 예정

## 4. 중복 생성 금지 원칙
- 신규 모듈(1·2·3조)은 자체 User/Student 테이블을 새로 만들지 않는다
- 이미 자체 테이블이 있는 경우 Core 테이블을 참조하는 방식으로 전환 (1조: 자체 테이블 폐지 / 2조: 참조 전용 유지)
- 3조는 현재 공동 편집 기능이 우선순위가 낮아 User 통합은 보류, 팀 정보 API만 우선 수신

## 5. 권한 기준
- **기준 필드**: `accounts_user.role` (varchar)
- 값: `tutor`(튜터) / `admin`(관리자) / `student`(학생) 3종
