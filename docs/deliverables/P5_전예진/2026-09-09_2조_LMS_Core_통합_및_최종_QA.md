### 2.2 LMS DB 및 Core 데이터 연결

LMS 업무 데이터는 `assignment_lms` DB를 사용하고, 사용자·팀·회차 등 공통 데이터는 Core가 소유하도록 분리하였다.

```text
Core DB
→ User / Team / Round / EvaluationResult

assignment_lms DB
→ Lecture / Assignment / Submission / Evaluation / GitHub Sync
```

DB Router를 통해 LMS 업무 데이터와 Core 데이터를 분리하고, LMS에서 Core 공통 데이터를 임의로 쓰지 않도록 연결하였다.

### 2.3 LMS 점수 → Core 평가 결과 반영 검증

- LMS 과제 평가 점수 집계
- `RoundScore` 생성 확인
- LMS 점수의 Core `EvaluationResult` 반영 확인
- TEAM / PEER / LMS 점수를 포함한 최종 점수 계산 확인
- 실제 평가 흐름 기준 점수 반영 확인

```text
LMS 과제 제출
    ↓
AI / 튜터 평가
    ↓
LMS 점수 집계
    ↓
RoundScore
    ↓
Core EvaluationResult
    ↓
최종 평가 점수
```

## 7. 검증 방법

### LMS → Core 점수 반영

1. 평가 대상 LMS 과제를 준비한다.
2. 학생 계정으로 과제를 제출한다.
3. AI/튜터 평가를 수행한다.
4. LMS 점수 집계 결과를 확인한다.
5. `RoundScore` 생성 여부를 확인한다.
6. Core `EvaluationResult`의 LMS 점수 반영 여부를 확인한다.
7. 최종 평가 점수를 확인한다.

### LMS 기반 팀 편성

1. LMS 점수 반영 비율을 설정한다.
2. 팀 편성 대상 과제를 선택한다.
3. 학생별 LMS 점수 집계 상태를 확인한다.
4. 팀 편성 계산을 수행한다.
5. 생성된 팀 구성을 확인한다.
6. 저장 후 새로고침하여 결과 유지 여부를 확인한다.

### 외부 연동

1. GitHub OAuth 인증을 수행한다.
2. 과제 제출물을 GitHub에 동기화한다.
3. 실제 저장소 반영 여부를 확인한다.
4. Gemini API를 호출하여 AI 평가를 수행한다.
5. 평가 결과 저장 여부를 확인한다.
