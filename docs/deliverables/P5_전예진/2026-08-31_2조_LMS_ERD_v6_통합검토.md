# 2026-08-31 2조 LMS ERD v6 통합 사전 검토

## 1. 목적

* 2조 LMS ERD v6를 기준으로 4조 AX2 Core 통합 시 필요한 데이터 구조 확인
* 2조 LMS 고유 데이터와 4조 AX2 Core 공통 데이터의 구분 기준 재확인
* 실제 코드 전달 전 Model / FK / Migration 영향 범위를 사전 파악
* 코드 전달 이후 실제 구현과 문서 내용을 비교할 수 있도록 검토 기준 정리
* 향후 LMS 통합 및 QA 진행을 위한 확인 항목 준비

## 2. 오늘 수행 내용

* 2조에서 공유한 **ERD v6** 내용 전체 검토

* LMS의 주요 엔티티 및 데이터 관계 확인

  * Assignment
  * Submission

  * AccountsUser

  * TeamsTeamMembership
* 2조 LMS와 4조 AX2 Core 간 DB 분리 구조 확인

* 외부 데이터는 `managed=False` 및 VIEW/헬퍼를 통한 읽기 전용 참조 구조 확인

* `final_score`가 튜터 공식 평가 점수를 캐시하는 구조 확인
* 팀장/대표자 개념이 폐기되고 팀원 누구나 팀 과제를 제출할 수 있도록 변경된 사항 확인
* ERD에 명시된 미확정 사항 및 통합 시 추가 확인이 필요한 항목 확인

## 3. 검토 결과

### 3-1. 공통 데이터 기준

| 데이터                         | 통합 기준       |
| --------------------------- | ----------- |
| User                        | 4조 AX2 Core |
| Student / Round Participant | 4조 AX2 Core |
| Team                        | 4조 AX2 Core |
| TeamMember                  | 4조 AX2 Core |
| Round                       | 4조 AX2 Core |

2조 LMS에서 공통 데이터를 별도로 소유하지 않고 4조 AX2 Core의 데이터를 참조하는 기존 통합 방향을 유지한다.

### 3-2. 2조 LMS 고유 데이터

* Lecture
* Lesson
* LessonMaterial
* Assignment
* Submission
* SubmissionFile
* AiEvaluation
* Evaluation
* Todo

위 데이터는 LMS 기능을 위한 2조 고유 영역으로 분류하고, 실제 코드 확인 후 4조 통합 시스템에 적용하는 범위를 확정한다.

### 3-3. 주요 통합 확인 대상

코드 전달 이후 다음 영역을 우선적으로 확인한다.

* Django Model 구조
* `db_table` 설정
* 외부 User / Team 참조 방식
* Model 간 FK 구조
* `managed=False` 적용 여부
* DB Router 및 DB 연결 구조
* Migration 생성 및 적용 범위
* Submission의 개인/팀 구분 로직
* AI Evaluation / Evaluation 관계
* `final_score` 및 `is_locked` 동기화 로직
* 팀원 여부 검증 로직

### 3-4. ERD에서 확인된 주요 규칙

* `SUBMISSION.student_id`와 `SUBMISSION.team_id`는 동시에 사용할 수 없음
* 개인 과제는 `(assignment_id, student_id)` 기준으로 1건 제출
* 팀 과제는 `(assignment_id, team_id)` 기준으로 1건 제출
* 팀 과제는 팀원 누구나 제출 가능
* 튜터 공식 평가 저장 시 Submission이 잠금 상태로 변경
* `EVALUATION.score`가 현재 `final_score`의 기준값
* AI 평가는 재생성 가능하며 기존 평가 데이터를 덮어씀

## 4. 통합 영향 및 사전 확인 사항

### 통합 시 확인할 부분

* 2조 LMS의 User / Team 참조가 4조 AX2 Core 구조와 실제로 일치하는지 확인
* 기존에 협의한 VIEW 구조가 실제 코드에 적용되어 있는지 확인
* 외부 DB 참조 방식이 현재 통합 시스템의 DB 구조와 충돌하지 않는지 확인
* LMS Model의 FK가 실제 Core Model 또는 외부 참조 구조와 호환되는지 확인
* Migration 과정에서 기존 4조 테이블에 영향을 주는 부분이 있는지 확인
* 2조에서 별도로 생성한 User / Team 관련 Model이 존재하는지 확인
* 기존 ERD와 실제 Model 간 차이가 있는지 확인

### 현재 확인할 수 없는 부분

현재 2조 실제 코드가 전달되지 않았으므로 다음 항목은 아직 검증하지 않는다.

* 실제 Django Model 구현
* 실제 FK 구현
* 실제 Migration 상태
* 실제 DB Router 구현
* 실제 VIEW 연동 코드
* 실제 제출 및 평가 기능 동작 여부
* PRD/ERD와 실제 구현 간 차이

따라서 위 항목은 코드 전달 이후 확인 대상으로 유지한다.

## 5. 미확정 사항

ERD v6에서 다음 사항은 아직 확정되지 않은 것으로 확인하였다.

* `final_score` 최종 집계 방식

  * 현재는 튜터 `EVALUATION.score`를 그대로 복사
  * 향후 가중치 또는 rubric 적용 여부 논의 필요
* 점수 `0~100` 범위에 대한 DB CHECK / Validator 적용 여부
* 평가 rubric 세부 구조
* `ASSIGNMENT.weight_tier`의 실제 가중치
* 인증 방식
* 과제 삭제 시 Submission / Evaluation 처리 방식
* AI 평가 자동 실행 및 공개 시점
* 강의 영상 및 교안 관련 세부 정책

위 항목은 코드 통합 전 반드시 모두 수정할 필요는 없으며, 실제 통합에 영향을 주는 항목을 우선적으로 확인한다.
